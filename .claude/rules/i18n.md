# Languages (uk / en)

The app ships in Ukrainian and English. `state.language` (`'uk' | 'en'`, defaults to the device language via `expo-localization`) drives UI strings, dates and demo data.

- **No hard-coded UI copy in components.** Every user-facing string goes through `t('area.key', params)`.
  - In components: `const { t, lang } = useT()` from `@/i18n` (re-renders on language change).
  - In plain functions (formatters, helpers): `t` from `@/i18n/translate` — never import `@/i18n` there (it pulls in the store and creates a cycle).
- **Dictionaries:** `src/i18n/locales/uk/<area>.ts` is the source of truth; `src/i18n/locales/en/<area>.ts` mirrors every key (typed via `Translation<typeof Uk>`, so a missing key fails `npm run typecheck`). Areas: `common`, `onboarding`, `feed`, `room`, `chat`, `profile`. Shared words (actions, tabs, time, counters) live in `common`.
- **Params and plurals:** `'Ти і {name} обоє…'` with `t(key, { name })`. Counts use plural entries — `{ one, few, many }` in Ukrainian, `{ one, other }` in English — and `t(key, { count })`.
- **Grammar:** Ukrainian case forms (`з Даринкою`, `Написати Даринці`, `у «Кульбабі»`) and gendered verbs (`йде сама/сам`) stay in the Ukrainian branch of a helper; the English branch uses the plain name. Branch with `lang === 'uk'` or `tr({ uk, en })` from `@/i18n`.
- **Dates:** `src/lib/time.ts` formatters are already localized (`dayLabel`, `whenLabel`, `longDate`, `countdown`…).
- **Demo data:** `src/data/mock.ts` stores text as `{ uk, en }` pairs; its exported arrays are live bindings switched by `setDataLanguage`. Read them at use time — never capture `events`, `users`, `interests`… into module-level constants.
- **Emoji** in UI copy (`👋 Я йду`) belongs to the string in both languages.
